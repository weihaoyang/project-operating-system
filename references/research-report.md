# Research-first report

Use this structure before implementing a new product, system, or major feature:

1. Target and success condition.
2. Search scope and date.
3. Candidate projects: repository, license, activity, architecture, dependencies, tests, maturity.
4. Failure modes and traps found in source, issues, or releases.
5. Reusable designs and designs to avoid.
6. Recommendation: selected approach and why.
7. Proposed architecture and boundaries.
8. MVP and explicit non-goals.
9. Ordered implementation plan with verification gates.
10. Open decisions and risks.

End with a clear confirmation request. Do not create project files or output implementation code before confirmation unless the user explicitly opts out.
